### Lekcija 1 — Zašto TypeScript uopšte postoji ❓

JavaScript je dynamically typed jezik. To znači da JS ne proverava tipove dok pišeš kod — greška se pojavi tek kada program pokreneš (runtime error).
```Bash

// ❌ Čist JavaScript — ovo neće pući dok ne pokreneš kod
function pozdrav(ime) {
  return "Zdravo, " + ime.toUpperCase();
}

pozdrav(42); // 💥 Runtime Error: ime.toUpperCase is not a function
```

TypeScript je statically typed — greška se uhvati pre pokretanja, dok još pišeš:
```Bash

// ✅ TypeScript — greška se vidi odmah u editoru
function pozdrav(ime: string): string {
  return "Zdravo, " + ime.toUpperCase();
}

pozdrav(42); // 🔴 Editor ti odmah kaže: Argument of type 'number' is not assignable to parameter of type 'string'
```

TypeScript nije novi jezik — to je JavaScript sa type annotations. Kada se kompajlira (transpile), dobija se čist JS koji browser razume. TS postoji samo da bi tebe, developera, zaštitio od grešaka.

### Lekcija 2 — Primitivni tipovi (The Building Blocks) 

U TS-u, svaka vrednost ima tip. Počinjemo sa primitivima:
```Bash

// --- PRIMITIVNI TIPOVI ---
let ime: string = "Marko";
let godine: number = 25;        // nema int/float razlike kao u C# — samo number
let jeAktivan: boolean = true;

// --- ARRAYS ---
let gradovi: string[] = ["Beograd", "Novi Sad", "Niš"];
let ocene: number[] = [8, 9, 10];

// Alternativna sintaksa (videćeš obe u projektima)
let tagovi: Array<string> = ["typescript", "javascript"];

// --- UNION TYPES — vrednost može biti VIŠE tipova ---
// Ovo je jedna od najvažnijih TS funkcionalnosti
let id: string | number = "abc-123";
id = 456; // ✅ OK — oba su dozvoljena

// --- LITERAL TYPES — vrednost mora biti TAČNO ovo ---
let smer: "levo" | "desno" | "gore" | "dole" = "levo";
smer = "dijagonalno"; // 🔴 Greška!

// --- TUPLE — array sa FIKSNIM brojem i tipovima elemenata ---
let koordinate: [number, number] = [44.8, 20.5]; // [latitude, longitude]

// --- NULL & UNDEFINED ---
// Uz "strict" mode u TSConfig, null i undefined se moraju eksplicitno navesti
let korisnik: string | null = null; // može biti string ili null
```

Ključna razlika: type inference (zaključivanje tipa)

TS je dovoljno pametan da sam zaključi tip bez anotacije:
```Bash

let grad = "Beograd"; // TS zna da je ovo string — ne moraš pisati : string
let broj = 42;        // TS zna da je number

grad = 100; // 🔴 Greška! TS je već zaključio da je grad string
```

Pravilo: Piši anotacije samo kada TS ne može sam da zaključi tip (npr. function parametri, prazni arrays).
